# Campus Toolbox · 校园工具箱

原生 Android · 当前版本 1.3.1（versionCode 5）· Android 8.0+

这是可以安装使用的原生 Android 应用，不是网页截图或静态演示。活动照片水印可独立使用；快递模块只提供官方应用的快捷入口，不聚合账号、短信或物流数据。

## 安装与使用

仓库提供源码；按下方构建步骤生成 `app/build/outputs/apk/debug/app-debug.apk` 后安装，需要 Android 8.0 / API 26 或以上。应用显示名为“校园生活助手”，使用独立包名 `cn.campuslife.assistant`，不会替换参考用的 QuickJump。当前本地交付 APK 为开发测试签名，不是商店正式发行版。

本机的 `交付/`、`历史归档/`、`verification/` 和旧设计预览不上传 Git；没有 GitHub Release 安装附件，不要把网页设计稿当成可运行应用。1.3.1 使用绿白原生界面，上方六标签与位置选择，下方照片预览，可选纯内容或字段名+内容。

旧测试版仅能用相同签名的 APK 覆盖升级；其他电脑自行构建的 debug 签名通常不同，不能保证覆盖已有安装。不要为试装擅自卸载旧版，以免丢失本机资料和草稿。

首页 → 开始制作 → 从相册选择 / 拍照 → 点选六个字段、编辑资料并在下方预览 → 保存照片 → 选择命名字段或改名 → 确认保存。首页最上方三个快递按钮直接向对应 App 发起跳转，无须进入分类。

- 可以直接选图，不必先注册或填写资料。
- 首页右上“设置 → 我的校园资料”或编辑器“编辑资料”可填写学院、班级、姓名、座号、学号；选中拍摄时间后，可在标签下方直接编辑时间。
- 学号初始关闭，资料初始为空。空字段不打印，不会预填虚构身份。
- 水印只有学院、班级、姓名、座号、学号、拍摄时间六项。像导出命名一样用编号标签控制显示，按点选顺序排列；取消后重新选择会排到末尾。“水印内容”旁的“只显示内容”默认勾选；取消后会附带“姓名：”“班级：”等字段标签，选择自动记住，预览与导出同步。学校、专业、活动名称、地点和备注不再提供；覆盖升级不删除旧资料值，但它们不会印到照片上。
- 导出命名默认按“班级_姓名_座号”组合，可从六项中自行点选，按点选顺序组成文件名，空值跳过、路径字符替换；资料都为空时使用“水印照片_时间”。学号默认不参与命名。JPEG / PNG 后缀随格式切换，不写入水印。
- 手动改过的名称不会被资料更新覆盖；“重新生成”恢复自动组合。命名字段选择存在本机，手动名称仅保留在当前编辑会话，取消不保存图片；旋转会保留未确认的命名与格式，不自动导出。
- 主页面只保留当前一种水印设置，不再显示模板列表、模板保存和“内容 / 样式 / 模板 / 大预览”四个分页。新用户默认白字、半透明深色底、右下位置。六字段下方“水印位置”可选左上、右上、左下、右下、底部居中；仍可直接拖动定位，拖动后显示“自由移动”；JPEG / PNG 在导出弹窗中选择。
- 横屏时选项区可滚动，并为照片和保存操作保留空间；空图时从“更换照片”进入相册或相机。弹出软键盘时临时收起预览及顶部选图区，为输入内容留出空间；关闭键盘后自动恢复，水印设置不会丢失。
- 字段选择、顺序与当前设置自动记住，不再要求管理多个模板。覆盖升级不会删除旧个人模板数据；仅旧版完全未改过的默认左下迁移为右下，已拖动/已调样式的位置保留，新版主动选左下后会记住；旧模板管理暂不在界面展示。
- Android 10+ 保存到相册 `Pictures/校园生活助手/`；Android 8–9 使用系统“另存为”选择保存位置。分享使用系统分享面板，由用户主动选择接收应用。
- 保存生成新相册条目，系统可能为同名文件加序号；不会覆盖相册原图或前一次导出。关闭重开会恢复最后一张照片副本、资料、编辑设置和命名字段选择。

## 图片与隐私边界

- 支持 JPEG、PNG（含透明 PNG）；不支持 HEIC、GIF、RAW。单张最多 64 MiB、8000 万像素，超限会提示，不静默读取全部文件。
- 导入时保留应用私有的原文件副本，预览才使用缩略图。EXIF 1–8 包括镜像与旋转都有统一坐标处理。
- 优先按原始方向和分辨率输出，JPEG 质量 96，PNG 无损编码。内存不足时提示用户明确选择较小尺寸，不自动降分辨率；无法处理的尺寸仍可能提示失败，可选更小尺寸或照片。
- 透明图导出 JPEG 使用白底；预览也显示相同白底。PNG 保留透明度。导出不复制原 EXIF/GPS 信息，拍摄时间作为用户可编辑的水印文字。
- 仅 EXIF `DateTimeOriginal` 作为拍摄时间；没有此字段则留空，不能用文件修改日期冒充拍摄时间。
- 应用自身没有网络、短信、相册全量读取、摄像头或定位权限。选图/拍照仅在点击后启动系统组件；系统相机可能自行询问相机权限。
- 资料、模板和照片不上传，关闭系统备份与设备迁移。主动分享才将生成图授权给所选接收应用；快递应用仍有它们自己的网络与隐私行为。
- 卸载或清除应用数据会删除本机资料、模板和草稿副本，不删除此前导出的相册图片。分享缓存会在后续导出时清理超过 24 小时的旧文件。

## 项目结构

```text
watermark-core/              纯 Kotlin 字段、模板、布局、坐标、方向与导出策略
app/src/main/.../data/       版本化 JSON 本地存储与恢复
app/src/main/.../image/      图片读取、方向修正、Canvas 渲染与新文件导出
app/src/main/.../ui/         首页、资料、编辑器、预览、共用字段标签、保留会话
app/src/main/.../express/    快递目录、配置校验、跳转、诊断和入口 UI
watermark-core/src/test/    布局与模型单元测试
app/src/test/              快递、安全配置、异步交付、草稿事务测试
app/src/androidTest/       Android 图片、存储、界面与生命周期测试
docs/                      版本实施记录与 GitHub 交接说明
AGENTS.md / STATUS.md       开发规范与当前状态
TASKS.md / CHANGELOG.md     待办优先级与版本历史
```

`LayoutEngine` 只处理经过方向修正的原图坐标。`WatermarkPreview` 用 `Viewport` 做包含留白的等比映射和拖动逆变换；`PhotoExporter` 在真正的输出 Bitmap 上绘制，二者使用相同的 `WatermarkRenderer`、字体度量与布局，不拿预览截图当成照片。

`EditorSession` / `RetainedWork` 在 Activity 重建时保留正在处理的任务，外部相册返回排队处理；保存按钮处理中禁用，重复导出不入队。草稿先提交新指针，再清理旧副本。

## 开发环境与构建

技术：Kotlin 2.0.21、Android 原生 Views / Canvas、AGP 8.13.0、Gradle 8.14.3、compileSdk 36、targetSdk 35、minSdk 26。开发使用 JDK 21，编译目标 Java 17。

主要运行依赖只有 AndroidX Core KTX、ExifInterface；测试使用 JUnit 4 和 AndroidX Test，没有引入图片上传 SDK、地图 SDK 或大型图像编辑框架。

用 Android Studio 打开工程，配置 JDK 17+（本机已验证 JDK 21）、SDK Platform 36 / Build Tools 35.0.0。用 `ANDROID_HOME` 指定 SDK，或在不提交的 `local.properties` 中填写自己的 `sdk.dir`。工程路径建议使用 ASCII；照片和导出文件名可使用中文。

在工程根目录运行 Windows PowerShell：

```powershell
.\gradlew.bat :watermark-core:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

macOS / Linux 使用相同 Gradle 任务：

```sh
./gradlew :watermark-core:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

这两种系统的命令入口已提供，但尚未在相应设备上实测。本机专用 `build.ps1` 不属于公开源码，不需要复制它的 E 盘路径。项目当前配置含阿里云 Maven 镜像及官方源；首次构建需要能够访问这些依赖源和 Gradle 分发地址。

首次获取依赖需要联网。APK 输出为 `app/build/outputs/apk/debug/app-debug.apk`。生成其他正式发行版本时须自行配置发布签名，不能使用这里的开发测试签名。

设备测试（请使用测试设备，测试会在相册创建标明测试用途的图片）：

```powershell
$env:ANDROID_SERIAL='emulator-5580' # 换成自己的 adb serial
.\gradlew.bat :app:connectedDebugAndroidTest
```

`UpgradeFixtureTest` 是专用模拟器发布验证夹具，只有显式传入 `upgradePhase` 才会执行，普通设备测试会跳过它。本机 `verification/` 中的历史升级脚本依赖旧 APK 和专用模拟器，不随仓库分发，也不是日常构建步骤。

## 快递模块与未实现范围

只保留拼多多包裹、拼多多身份码、抖音订单三个入口，首页可直接点。成功跳转不弹 Toast；完全打不开或只能回退应用首页时保留明确提示。右上设置中提供链接设置、诊断和抖音标准/极速版选择。目录参考 QuickJump 的公开入口思路，自行实现配置校验和跳转器，没有复制其应用身份或修改参考 APK。自定义链接只接受当前平台允许的协议，并固定目标包名；回退和诊断共用同一套有效配置。

“可发起跳转”只说明系统存在可处理 Intent 的应用，不保证第三方实际打开取件页。第三方版本、登录与链接有效性仍需真机验证；开发验证未登录用户快递账号，项目未发布到应用商店。

尚未做：真实校园地图/导航、物流聚合、批量水印、二维码/分享模板、负责人照片提交、后端账号与云同步。Android 8–9 和不同手机厂商的相机/相册交互尚需真机补测。

历史实际验证见 [1.3.1 实施与验证](docs/1.3.1-实施与验证.md)；本次上传范围与验证边界见 [GitHub 交接说明](docs/GITHUB.md)。原始日志留在开发机，不把历史记录冒充每次克隆后的测试结果。
